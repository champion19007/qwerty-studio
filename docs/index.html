The self-hosted anti-detect browser

Browser profiles that each look like a real, separate device — a coherent fingerprint, its own proxy, and a persistent session — managed from a clean web console or the CLI. A free, local alternative to Multilogin, GoLogin and AdsPower.

Why it exists

Coherence, not randomness

Most fingerprint tools randomise each value on its own — and that is exactly what gets them caught. Anti-bot systems don't read values in isolation, they cross-check them. A macOS user-agent with an NVIDIA GPU, or a 4-core phone claiming a 1440p screen, is an instant tell.

QWERTY picks a realistic device archetype first, then draws every value — OS, user-agent, GPU, screen, CPU, RAM, timezone, language — from that archetype's real-world pool. The result is an identity whose parts all agree, plus a live coherence check that proves it: validate() in the engine, and a real-time meter in the dashboard.

Quick start

Python 3.9+ for the engine, Node 18+ for the dashboard. The two halves are independent — run either, or both.

# 1. get it
$ git clone https://github.com/champion19007/qwerty-studio.git
$ cd qwerty-studio/engine

# 2. install the engine and a browser to drive
$ pip install -e ".[launch]"
$ playwright install chromium

# 3. make an identity and open it
$ qwerty create acct-01 --os windows --locale en-US
$ qwerty launch acct-01

# 4. optional: the web console (needs the api extra)
$ pip install -e ".[api]" && qwerty serve
$ cd ../dashboard && npm install && npm run dev

On Windows, start.bat installs everything and starts both halves in one double-click. The dashboard also runs standalone on sample data, so you can look around before installing the engine.

What's in it

Coherent identities

Desktop and Android fingerprints drawn as one device, so the model in the user-agent is the phone whose GPU, screen and RAM it reports.

Trust checker

Grades the real browser, not the config — 16 checks a fingerprinter would actually run, plus one-click auto-adjust.

Proxies & leaks

A managed pool with health checks, WebRTC and DNS leak tests, and a TLS/JA3 reader for the layer JavaScript can't touch.

Sessions that last

Cookies and localStorage persist between launches. Import or export a logged-in session as Cookie-Editor JSON, Playwright state or cookies.txt.

Collision detector

Finds profiles that share a fingerprint before a site links the accounts — the failure mode that quietly defeats the whole setup.

Drive it yourself

Attach Selenium, Puppeteer or Playwright to a live profile over CDP, so your automation inherits the identity rather than replacing it.

Pluggable stealth engines

QWERTY's job is to be the manager — identities, proxies, sessions, folders, coherence. The browser underneath is a backend you pick per profile.

EngineWhat it is
cloakCloakBrowser — patched Chromium, C++-level fingerprint/TLS/CDP changes. Recommended.
camoufoxPatched Firefox with its own coherent fingerprint generator.
patchrightRuntime-patched Playwright; fixes webdriver/CDP leaks the stock engine can't.
playwrightAlways available. Stock Chromium plus an injected stealth script.

Being honest about limits. Pure JavaScript injection has a ceiling — it cannot change the TLS/JA3 fingerprint or hide the CDP transport. For Cloudflare / DataDome-grade targets, pair a patched engine with a residential proxy and a warmed-up session. QWERTY stays the same manager over all of them.

Legitimate use

QWERTY is a tool for multi-account management done openly: agencies running many client ad accounts, QA and ad-verification testing, web-automation development, and privacy research — the same work commercial anti-detect browsers are sold for.

Do not use it for fraud, credential stuffing, spam, evading bans you have earned, or anything that breaks a site's terms or the law. You are responsible for how you use it.
